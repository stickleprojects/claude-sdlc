## Breaking: the framework's commands, agent and workflows start with `sdlc-`

Framework files outside `.sdlc/` now carry the `sdlc-` prefix, so nobody mistakes them for the project's own (#23).

| What | Before | Now |
|---|---|---|
| Commands | `/intent`, `/plan`, `/build`, `/pr`, `/next` | `/sdlc-intent`, `/sdlc-plan`, `/sdlc-build`, `/sdlc-pr`, `/sdlc-next`. `/sdlc` doesn't change. |
| Internal skills | `spec`, `po-review`, `review-findings`, `agent-identity`, `security-policy` | the same names with `sdlc-` in front |
| Skill stubs | `.claude/skills/<name>/SKILL.md` | `.claude/skills/sdlc-<name>/SKILL.md` |
| The verifier | `.claude/agents/verifier.md`, the `verifier` subagent | `.claude/agents/sdlc-verifier.md`, the `sdlc-verifier` subagent |
| Workflows | `.github/workflows/ci.yml`, `pr-title.yml`, `claude-review.yml`, `claude-mention.yml`, `spec-from-intent.yml`, `agent-evals.yml` | the same names with `sdlc-` in front |
| `make next`'s skill column | `plan`, `build`, … | `sdlc-plan`, `sdlc-build`, … |

These don't change:
- **Skill bodies** stay at `.sdlc/skills/<name>/SKILL.md`, and the agent's at `.sdlc/agents/verifier.md`. Your overrides in `.sdlc-local/` keep working where they are.
- **Job names** (`check`, `pr-title`, `claude-review`), which are what branch protection requires. Renaming the workflow files doesn't touch the required checks.

## New: upgrade steps travel with the sync

A sync now copies the upgrade steps of each release it brings in to `.sdlc/upgrade-pending.md`. `/sdlc` works through them and then deletes the file, and `make check` fails while the file exists, so a sync PR can't merge with its upgrade half done (#20). A release can also ship a script for the mechanical part of its upgrade, `.sdlc/migrations/<version>.sh`, which the sync runs. A release with breaking changes can't be published without upgrade steps.

## New: say no to an optional feature once

When `/sdlc` offers an optional feature and the team doesn't want it, it asks whether that means *not now* or *not for us*. *Not for us* is recorded in the project's `.sdlc.toml`, with the reason, and later updates stop offering the feature (#74):

```toml
[[features.declined]]
feature = "architecture decision records (ADRs)"
reason = "a short-lived prototype; the plan's Risks line is enough"
by = "Sam"
date = 2026-11-13
```

After each update, `/sdlc` lists the declined features it skipped, with who declined them and why, but doesn't offer them. `make validate` checks the entries. To adopt the feature later, delete its entry.

## Upgrade steps

These are for Claude, as part of `/sdlc`. Do them with the person, after the sync and before `make check`.

1. **Old files the sync kept.** The sync deletes the old stubs, verifier stub and workflows it had installed, unless the project had edited them. It lists any edited ones under *kept (the framework dropped these…)*. For each one:
   - show the person the project's edit (`git diff <the commit of the last sync> -- <file>`, or compare it with the new file);
   - carry the edit across:
     - a workflow edit goes into the new `sdlc-<name>.yml`, where later syncs merge it as they did before;
     - a skill stub's edit goes into the new `.claude/skills/sdlc-<name>/SKILL.md`;
   - delete the old file.

   Ask before each one. Don't leave both. Two copies of a workflow both run on every PR, and two copies of a skill show up twice in the `/` menu.
2. **The project's own files that name the old commands, agent or workflows.** Search outside `.sdlc/`, `changes/` and `docs/release-notes/`:
   ```
   git grep -nE '(^|[^[:alnum:]_./<>*-])/(intent|plan|build|pr|next|spec|po-review|review-findings)\b|verifier subagent|workflows/(ci|pr-title|claude-review|claude-mention|spec-from-intent|agent-evals)\.yml' -- . ':!.sdlc' ':!changes' ':!docs/release-notes'
   ```
   Typical places are `CLAUDE.md`, the README (a CI badge links to `actions/workflows/ci.yml`), the project's docs, its overrides in `.sdlc-local/`, and its own scripts or workflows (`gh workflow run ci.yml`). Show the person each hit and change the ones that mean the framework's command, agent or workflow, not a path of the project's own. Leave merged artifacts in `changes/` alone, because they're history.
3. **Branch protection and rulesets.** The required checks are job names, so they don't change. Confirm with `gh api repos/{owner}/{repo}/branches/main/protection --jq .required_status_checks.contexts`. If the repo has a ruleset that requires a workflow by its file path, point it at the new file name.
4. **Tell the team** in the sync PR body that the commands are now `/sdlc-intent`, `/sdlc-plan`, `/sdlc-build`, `/sdlc-pr` and `/sdlc-next`, and that `/sdlc` is unchanged. A Claude Code session that's already open needs restarting to see the new names.
5. **Check:** run `ls .claude/skills .claude/agents .github/workflows`. The only unprefixed entries left should be the project's own. Then run `make check`.
