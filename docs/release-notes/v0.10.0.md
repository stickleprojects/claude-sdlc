## Breaking, for repos with auto-merge: the review gate is now the `claude-review` status

With `SDLC_AUTO_MERGE` on, main used to require the review job's own `review` check. A job skipped by its `if` (an unrelated label, say) still posts a passing `review` check on the head commit. That could satisfy the requirement before the real review finished (#101).

Now the review job posts its own **`claude-review`** commit status:
- **pending** when it starts;
- **success** once the review summary is posted, or, for a PR that changes a `claude-*.yml` workflow, with a description saying a code owner reviews it by hand;
- **failure** if the review fails.

A skipped job posts nothing, so it can't satisfy the gate.

**What changes:**
- **Bootstrap** requires `claude-review` instead of `review` in team mode with auto-merge on, and drops the old `review` check whatever the mode.
- **`scripts/auto-merge.sh`** counts only `claude-review` as the gate. On a branch that still requires `review`, it skips with a warning to re-run bootstrap. It also never auto-merges a PR that changes a `claude-*.yml` workflow, because the AI review can't run on one.
- **Until bootstrap is re-run,** nothing breaks: PRs still need the old `review` check and a person's approval, but the pipeline doesn't turn auto-merge on.

## Fixes from the v0.6.0 → v0.8.0 sync review (#101)

- **`SDLC_AUTO_MERGE=off` is off everywhere.** Case doesn't matter, and unset, empty or `off` means off. The rule is written once (`scripts/auto-merge.sh --method`), and the workflow, bootstrap, the sync and `scripts/request-review.sh` all follow it, so a repo set to `off` no longer runs a review on every push.
- **No stale gates when auto-merge is off.** Bootstrap stops requiring `claude-review` and deletes a leftover `SDLC_AUTO_MERGE_CONFIRMED`.
- **Rulesets-only branches decide for themselves.** A leftover confirmation no longer stands in for a ruleset that doesn't dismiss stale approvals. Organization variables past the first 30 are read too.
- **Merged specs' criteria are left alone.** `make validate` checks the `- AC<n>` form only in specs the branch adds or edits.
- **The sync reports the repo's own scripts that aren't executable,** with the fix command, and leaves them unchanged.
- **The "AI review can't run" note** is also posted on the push that first changes a `claude-*.yml` workflow.

## Upgrade steps

These are for Claude, as part of `/sdlc`. Do them with the person, after the sync and before `make check`.

1. **Check whether this repo uses auto-merge.** Run `scripts/auto-merge.sh --method`.
   - It prints nothing: auto-merge is off. Go to step 3.
   - It exits 1: the variable can't be read with this login. Ask the person.
2. **With auto-merge on, switch main to the new gate.** The person runs this themselves, because it needs admin access to the repo:

   ```
   scripts/bootstrap-github.sh --mode team
   ```

   It replaces the `review` check with the `claude-review` status and re-confirms the protection. Check its step 6 line: it should say "the claude-review status (auto-merge is on)", and "the old review check is no longer required" if `review` was required before. Until this is done, `scripts/auto-merge.sh` won't enable auto-merge on new PRs, and says why.
3. **With auto-merge off, check for stale gates.** If main requires `review` or `claude-review`, or `SDLC_AUTO_MERGE_CONFIRMED` is set (bootstrap's step 6 and the sync's settings report show both), the person runs `scripts/bootstrap-github.sh --mode <solo|team>` once. It removes them. Otherwise, nothing to do.
4. **Repo-owned scripts.** If the sync listed "your own scripts that aren't executable in git", offer to run the `git update-index --chmod=+x` command it gives, and commit the result in the sync PR.
5. **Report** in the sync PR body: whether auto-merge is on, whether bootstrap was re-run (or is still waiting for the person), and any scripts that were made executable.
