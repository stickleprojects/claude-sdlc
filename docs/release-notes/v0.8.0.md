## Breaking: plans need a Descopes section

`plan.md` has a new required section, `## Descopes`, after Risks. It lists everything the plan leaves undone, untested or unchecked, and everything a person has to try by hand, each with the engineer's approval:

```
## Descopes

- Descope: dock widget tests because the editor can't run headless in CI. Approved: Sam, 2026-11-10.
- Human check: walk the new room and check the lighting because no test measures it. Approved: Sam, 2026-11-10.
```

A plan with none writes `None.`. Until now, descopes were `Descope:` lines in Risks, where they were easy to miss when approving a plan (issue #95).

**What `make validate` checks.** It checks only a `plan.md` that your branch adds or edits compared with main, committed or not. Plans merged before this release stay valid until someone edits them. In an added or edited plan, it fails when:

- the Descopes section is missing, empty, or still has the template's text;
- an entry isn't a `- Descope:` or `- Human check:` line;
- an entry has no `Approved: <name>, <date>`;
- a `Descope:` line is still in Risks.

**Human checks** (issue #32). A check that no test can do (feel, timing, hardware, the real game or editor) is written as a `Human check:`. The verifier reports each one as PENDING, never PASS, and finishes with `VERDICT: PENDING (<k> human checks)` when nothing else fails. `/build` lists them in the PR under **To check by hand**, for the owner to try before merging, and the Claude review flags a PR that leaves them out.

**What to do after syncing.**

- Nothing, for plans that are already merged.
- A plan PR that's open when you sync: add the `## Descopes` section, and move any `Descope:` lines out of Risks into it.
- A plan you edit later, for example to rework it mid-build: add the section as part of that edit.
