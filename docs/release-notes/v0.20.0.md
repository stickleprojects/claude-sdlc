## The sync PR gets its AI review

From v0.19.0, this release changes no `sdlc-claude-*.yml` workflow, so the sync PR gets a Claude review like any other PR. 12 of the last 18 releases changed one, and their sync PRs got no AI review of any file: a code owner reviewed them by hand. A repo on a release older than v0.19.0 still gets the older workflow changes in this sync, so its sync PR still has no AI review. #293 will close that gap for good: the review will run from main's copy of its workflow.

## Workarounds you can drop

- **A withdrawn change no longer gets a spec (#286).** `spec-pr.sh pending` skips a change with a `Withdrawn:` line, or a `change.toml` that says `withdrawn`, and says so in the run's log. You no longer need to cancel the spec run, or close the spec PR it opened, after a merge that touches an intent or bug.
- **A re-review with no new push gets its label (#287).** With auto-merge on, `request-review.sh` no longer counts a finished review of the head as "this push already started a review". The review skills pass `--again` when nothing was pushed since the last review, for example after an `Approved:` reply. You no longer need to add the `review` label by hand.
- **Moving a change on the roadmap leaves its spec alone (#280).** Editing only an intent's `Milestone:` or `Adjustment:` lines no longer marks its spec out of date in `make next`.
- **One reply on a descope thread leaves no red job (#283).** The `descopes` job no longer runs twice, with the second run cancelling the first and leaving a failed check.

## Skills use the change their copy is for (#279)

With no change named, `/sdlc-build`, `/sdlc-plan`, `/sdlc-next` and `/sdlc-pr` use the change this copy of the code is for, from `$SDLC_CHANGE`, the branch's slug or the worktree folder's name, and say which in one line rather than asking. Name another change and yours wins, with a warning. A worktree can be named by the change's number alone (`claude --worktree 0063`); the plan gate and the test lock recognise it. A skill override in `.sdlc-local/` keeps its old behaviour.

## Review summaries

The summary leaves out its "how to handle the findings" line when no finding is open (#289). In a repo with `Change tracking: issues`, the line asks Claude Code to work through the PR's findings, rather than naming `/sdlc-pr`.
