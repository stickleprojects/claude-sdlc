## Optional: architecture decision records (ADRs)

Some architecture decisions build up over several changes, such as "should we adopt a framework instead of building this by hand again?". No single change raises them. This release lets a repo record its decisions as ADRs, so `/plan` can check each new plan against them. Nothing changes until you add one: a repo without `docs/adr/` behaves exactly as before.

**What's new after you sync**

- `templates/adr.md`: copy it to `docs/adr/0001-<slug>.md`. Its **Revisit when** section lists concrete triggers, one per line, such as "a plan hand-builds navigation state" or "a plan relies on an undocumented internal of <library>".
- `/plan` reads `docs/adr/` and checks each plan against every accepted ADR's triggers. When one is met, it asks the engineer whether to keep the current architecture or take it to the tech lead. It records the outcome in the plan's **Risks** as `Architecture decision needed: …`. Even without ADRs it asks "build or adopt?" whenever a plan builds by hand what a common library provides.
- The Claude review reports a plan that meets a trigger without saying so (Important).
- `make validate` checks each ADR's sections and status, and that an accepted one names at least one trigger.

**To adopt it** (the tech lead or architect owns ADRs; see `docs/roles.md`)

1. List the decisions the repo already depends on, such as the client framework and router, state handling, datastore and hosting.
2. For each one, write an ADR from the template. Say why it was chosen and what would make you revisit it. Past plans under `changes/` that built something by hand are a good source of triggers.
3. Set **Status** to `accepted (<who>, <date>)` and merge them in an ADR PR.

You can ask Claude to draft them: "Read the code, dependencies and past plans, and draft proposed ADRs for the decisions this repo has already made, with Revisit when triggers." Review them before accepting. #74 tracks making this an offer the sync makes for you. #72 tracks choosing no ADR process, or an external one.

## Optional: your own "nothing here" words

`make validate` reads some words as "nothing written" in a section that must have content (`None`, `TBD`, `N/A` in an ADR's Revisit when), and only `None.` as "nothing open" in a section that must be cleared (build.md's Questions before approval). The defaults are in `tools/sdlc/src/sdlc/placeholders.toml`. To change them for your repo, add `.sdlc.toml` at its root. The sync never touches that file.

```toml
[placeholders.nothing_written]
additional_keywords = ["pending"]   # adds to the framework's words; `keywords` replaces them
```
