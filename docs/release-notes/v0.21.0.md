## Upgrade steps

1. **Check your runner, if it's self-hosted.** The synced workflows now use `actions/checkout@v7`, `actions/upload-artifact@v7` and `actions/create-github-app-token@v3` (#304), which need runner v2.327.1 or later (Node 24). GitHub's own runners already have it. Behind an HTTP proxy, `create-github-app-token` v3 also needs `NODE_USE_ENV_PROXY=1`.
2. **Update an allowlist that names exact versions.** If your repo's Actions settings allow actions by exact version rather than `actions/*`, add those three versions before you merge the sync PR, or every workflow fails at job start.
3. **Review the sync PR by hand.** It moves the Claude review onto `pull_request_target`, so main's old copy of the review can't run on it. The new `sdlc-claude-review-transition.yml` marks `claude-review` as passed ("No AI review: this PR moves the review onto main's copy, so a code owner reviews it by hand") and says so in a comment. Read `.github/`, `.sdlc/hooks/` and `.claude/settings.json` with extra care. This is the last sync PR without an AI review.
4. **Nothing to set.** No new variable, secret or branch-protection rule. `claude-review` is still the required status.

## The Claude review runs main's copy of its workflow (#293, ADR 0001)

The review runs on `pull_request_target`, so GitHub runs the copy of `sdlc-claude-review.yml` on your default branch, not the PR's. A PR can't change how its own review runs: its steps, prompt and allowed tools all come from main. A PR that changes a workflow gets a full AI review like any other, sync PRs included. Before, two sync PRs in three got no AI review of any file.

The job checks out main at the workspace root, and the PR's head in `pr/` as data only: no credentials, and nothing in it is run, sourced or made. The clause check runs main's tool over the PR's spec and plan, copying only regular files, never the PR's Makefile. Fork PRs are still never reviewed, and they get no step at all.

A run's name is now `Claude review of #<pr> at <sha>`. The after-review gate, `request-review.sh` and `review-current.sh` read the PR and commit from it, since a `pull_request_target` run's own branch and head are main's.

## A CI change needs a person's approval (#307, #308)

A PR that changes a file setting CI's rules gets one thread from the review job: `CI change: needs approval`, listing those files. The files are everything under `.github/`, `.sdlc/hooks/`, `.claude/settings.json` and `uv.lock`. `claude-review` fails until a person replies `Approved: <name>, <date>` in it. Any other reply, resolving the thread or a re-review doesn't settle it, and neither does a bot or App. Where main needs no approving review (solo mode), that reply is the person's one recorded check before the merge. In a team repo it comes on top of the approving review, for now; #318 would let the approving review settle it. A later push that changes those files again gets a new thread. The AI review still reviews the files, as advice for the person approving.

Almost every sync PR changes a workflow or a hook, so expect this thread on each one from now on, starting with the sync after this one.

**Auto-merge** (`SDLC_AUTO_MERGE`) now skips any PR that changes a file on that list, not only one that changes a claude workflow. A person approves and merges it.

## The review posts as `github-actions[bot]`

Anthropic's token exchange refuses `pull_request_target` runs (anthropics/claude-code-action#713), so the review posts with the job's own token, as `github-actions[bot]`, not `claude[bot]`. It is still never the agent App, so Claude never reviews as the identity that wrote the code. Findings posted by `claude[bot]` before the sync still count, and the `@claude` mention workflow still posts as `claude[bot]`. A review App of its own is #311.

If you set `REVIEW_BOT` for the scripts, it's now a comma-separated list, defaulting to `github-actions[bot],claude[bot]`.

## Dependabot PRs are reviewed by hand (#303)

A Dependabot PR is never AI-reviewed: GitHub gives its runs no Actions secrets, `pull_request_target` included. So a person reviews every one by hand, and the PR's first comment says what to check: the new version's release notes for breaking changes (inputs, the runner version it needs), and who gets it through the sync.

What a person does depends on what the PR changes:

- **It changes `.github/` or `uv.lock`**, as an action bump or a lockfile update does. It also gets the `CI change: needs approval` thread, and `claude-review` stays red until a person reads the bump and replies `Approved: <name>, <date>` there. Then it turns green with "No AI review: a Dependabot update, so a person reviews it by hand", and the PR merges as usual.
- **It changes nothing on that list**, as a package bump elsewhere does. `claude-review` is green with that same text straight away, and the person's review is the approving review the branch asks for, if any, and the merge.

Auto-merge never applies to a Dependabot PR: it only turns on for PRs the pipeline opens.
