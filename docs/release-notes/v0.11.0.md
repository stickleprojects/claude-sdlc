## Breaking: the framework moves into `.sdlc/`

An update used to touch about 50 files across ten places in your repo (spellbound3d#130). Now everything the framework owns is in one folder, `.sdlc/`, and your changes to it go in another, `.sdlc-local/`, which the sync never writes (#133).

| What | Before | Now |
|---|---|---|
| Scripts, hooks, templates, prompts, `REVIEW.md`, framework docs, evals runner | `scripts/`, `.claude/hooks/`, `templates/`, `prompts/`, `REVIEW.md`, `docs/`, `evals/run.sh` | `.sdlc/…` at the same names |
| The `sdlc` tool | `tools/sdlc/src/sdlc` | `.sdlc/src/sdlc` |
| Skills and the verifier | full copies in `.claude/` | the body in `.sdlc/skills/` and `.sdlc/agents/`. `.claude/` keeps a stub with the name, description and one line that loads the body. Names don't change. |
| Hooks in `.claude/settings.json` | one entry per hook | one entry per event, calling `.sdlc/hooks/dispatch.sh`. Which hook runs when is in `.sdlc/hooks/hooks.tsv`, so settings stop changing on updates. |
| Framework make targets | in your Makefile | `include .sdlc/sdlc.mk` brings `new-change status next clauses exec-bits evals sync-sdlc`. Your Makefile keeps `setup fmt lint test validate check`. |
| The /build skill's `.gitignore` exception | a line in your `.gitignore` | `.gitignore` files inside the framework's folders |
| The sync's records | `.sdlc-version`, `.sdlc-files` | `.sdlc/version`, `.sdlc/files` |

## New: your changes in `.sdlc-local/`

Put your version of a skill, template, prompt, agent or `REVIEW.md` at the same path under `.sdlc-local/`. It's either a whole file, or a Markdown file starting with `<!-- extends -->` that replaces, appends to or prepends to only the blocks it names (headings, or `<!-- block: … -->` markers). The rest still comes from the framework, updates included. `.sdlc/scripts/resolve.sh <path>` prints the result.

- **Validate:** `make validate` fails on an override that no longer applies, for example one naming a block the framework removed.
- **Sync:** it lists your overrides of the files it changed.
- **Hooks:** you can add your own, as rows in `.sdlc-local/hooks/hooks.tsv`, but you can't replace the framework's. The framework's scripts, tool and hooks can't be overridden.
- **Security policy:** it's yours now. It lives in `.sdlc-local/skills/security-policy/SKILL.md`, and the framework ships only a placeholder.
- **The review** reads its rules through the resolver, as the PR's base branch has them, so a PR can't weaken the rules for its own review.

See `.sdlc/docs/overrides.md`.

## Upgrade steps

These are for Claude, as part of `/sdlc`. Do them with the person, after the sync and before `make check`.

1. **Come from v0.10.1.** A repo on v0.9.x or earlier syncs v0.10.1 first, does its upgrade steps (above all re-running bootstrap, so main requires `claude-review`), and merges that PR. Then it syncs this release. That keeps content changes and the move in separate PRs.
2. **The move is done by the sync, in one PR.** Your copy of the old sync script finds the new one, and the new one does the move:
   - It installs `.sdlc/` and deletes the old copies of files you hadn't changed.
   - Files you had changed move to their new path, with your edits merged into the new version. It lists them under *kept your local changes*. For each one, offer to turn the edit into an override in `.sdlc-local/`, usually an `<!-- extends -->` with one block, and put the framework's file back. Then the next update has nothing to merge. Ask before each one.
   - A security policy you'd edited moves to `.sdlc-local/skills/security-policy/SKILL.md`. Check it reads as the project's policy.
3. **Your Makefile.** The sync names what to change:
   - Add `include .sdlc/sdlc.mk` near the top.
   - Delete your copies of the targets it now brings. If one does something extra for this project, keep that part under a target with its own name.
   - Change any line the sync lists under *still use the old paths*. Usually that's `SDLC = PYTHONPATH=tools/sdlc/src …`: point it at `.sdlc/src`, or remove it, since `.sdlc/sdlc.mk` sets that default. Another stack can set `SDLC` in `.sdlc-local/local.mk`.
4. **Your own files that name old paths.** Change each line the sync lists under *still use the old paths*: for example `CLAUDE.md`, your own workflows or scripts, or tools that import `sdlc.*` with `PYTHONPATH=tools/sdlc/src`. Never edit `.sdlc/` to fix them.
5. **`.gitignore`.** If yours has `!.claude/skills/build/`, it can go. The framework's folders carry that exception now. Leave the rest of the file alone.
6. **Local edits to `.claude/settings.json`.** The framework's hook entries changed. If the sync merged your own entries (permissions, hooks of yours), move any hooks of yours into `.sdlc-local/hooks/hooks.tsv`, with their scripts beside it. Keep your permissions where they are.
7. **Check:** run `make check`. Then run `.sdlc/scripts/resolve.sh skills/build/SKILL.md | head -3` to confirm the resolver runs with this repo's Python, and `make status` to confirm the include works.
8. **Report** in the sync PR body:
   - which edits became overrides, and which stayed merged;
   - what changed in the Makefile;
   - any old-path lines left for a follow-up, and why.
