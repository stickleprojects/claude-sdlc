## New: no code before the plan

A hook now stops code edits on a change's branch or worktree (`build/0003-x`, `plan/0003-x`, …) until that change's `plan.md` is committed. On `main`, only `changes/`, `docs/` and top-level `*.md` can be edited, so code work starts on a branch (#44, #153). CI's `pr-title` job holds the same rule for edits made outside Claude.
- Branches that aren't named after a change, such as `chore/…`, `fix/…` and `docs/…`, are only exempt from the plan rule. Lint, security checks, CI and the review all run as before.
- A bug on the fast path is the exception (below): on `build/<slug>`, its committed `bug.md` and `spec.md` are enough.
- `SDLC_PLAN_GATE=0` turns the hook off for a session, but CI still checks it.

## New: a small bug's fix ships in one PR

A small bug with a known cause now goes into one PR by default. The PR holds the bug report, a short spec, the failing tests (committed first) and the fix. Approving it ships the fix, and it's titled `fix(<slug>): …` (#148, #154, #160). A bug that needs a product decision, a design decision, a new dependency or a data migration still takes the full path. `.sdlc/docs/bug-fast-path.md` says what the fast path skips. To keep every bug on the full path, add the line `Bug path: full` to the repo's `CLAUDE.md`.

## New: the review is quicker to settle

- **Every clause gap at once.** The review lists every uncovered clause of a requirement in one finding, and a re-review doesn't re-split text that hasn't changed (#160, #162).
- **Plan text kept in step.** When a PR changes a requirement, the plan text that depends on it (Approach, Steps, Verification rows) is checked in the same pass (#172).
- **A check before every push.** Before each push of a review fix, `/sdlc-pr` checks that `make next` reports nothing out of date, traces each changed requirement, and rereads the PR body for anything the push made false (#173).
- **Descopes need a person.** A "Descope: needs approval" thread is settled only by a person's reply on GitHub: `Approved: <name>, <date>`, or a reply that sends the work back. Resolving the thread isn't enough, and `claude-review` waits for that reply (#132).
- **Update branch needs no second review.** When a push only merges `main` in and leaves the PR's diff as it was reviewed (GitHub's **Update branch**), `claude-review` stays green, naming the review that still holds (#182). Any push that changes the diff still needs a review.
- **Logged tool calls.** The review logs its tool calls, and a review that runs but posts nothing says why, keeps its output and runs once more (#157, #167).
- **The right commit.** `request-review.sh` names the PR's head when it's run from another checkout (#168).

## New: tests before hand checks

Before Claude asks a person to try something by hand, during a build or a review and whether or not the plan lists it, it looks for a test that already checks it, and writes one if a script could (#171). The person is asked only for what no test can settle, or for a quick smoke test when scripting it would be a big effort. The test that's still owed then counts as a descope until someone approves it. In `/sdlc-build all`, the orchestrator now opens the PR itself, because it holds the decisions the PR body records (#170).

## Optional: run make check only after a clean review

Set the repo variable `SDLC_CHECK_AFTER_REVIEW` to `on` (`gh variable set SDLC_CHECK_AFTER_REVIEW --body on`), and a PR's `make check` waits for a Claude review with no open Important thread (#163). A review that asks for changes then never costs a `check` run, which matters most on a self-hosted runner that runs one job at a time. Use it with `SDLC_AUTO_MERGE`. Without auto-merge, a push waits for the `review` label before `check` runs. The `check` label runs `make check` straight away, whatever the review says. Nothing changes until the variable is set.

## Optional: a build PR that amends its own plan

Set the repo variable `SDLC_BUILD_AMENDS_PLAN` to `on`, and a decision made during a build that changes the plan, or a spec clause, can go into the build PR. It no longer needs a separate plan or spec PR (#174). Claude records each decision in build.md (who decided, when, and their words), amends `plan.md` (and `spec.md` for a clause), and lists each amendment under `## Plan changes` in the PR body. The review raises them all as one "Plan changes: needs approval" thread, and a person's single `Approved: <name>, <date>` reply approves them. A line in build.md is never the approval. The PR keeps its `feat` or `fix` title. Nothing changes until the variable is set.

## Upgrade steps

These are for Claude, as part of `/sdlc`. Do them with the person, after the sync and before `make check`.

1. **Allowed actions.** The Claude review now keeps a failed review's output with `actions/upload-artifact` (#157). If the repo allows only selected actions (Settings > Actions > General), the sync's settings report names any action the list leaves out, under *allowed actions leave out*. The review workflow doesn't start until that action is added. Tell the person, who adds each one as `<name>@*` (Claude can't change repo settings for them), and keep the sync PR a draft until they have. With no such line, there's nothing to do.
2. **No code before the plan.** Tell the person in one line that code edits on a change's branch now wait for its committed `plan.md`, and that `chore/…`, `fix/…` and `docs/…` branches are only exempt from that rule. If a change's branch is mid-build without a committed plan.md, say which one; the hook will block code edits there until the plan merges.
3. **A self-hosted runner.** Two new workflows, `sdlc-descopes.yml` and `sdlc-check-after-review.yml`, run on `SDLC_RUNNER` when it's set. So do the new scripts `check-gate.sh`, `check-plan-first.sh`, `descopes-decided.sh`, `descopes-status.sh` and `review-denials.sh`. If the runner allowlists jobs or workflows, tell the person so they can check it before the sync PR's first run. Never loosen a runner's lockdown yourself.
