## The sync checks your repo's secrets and variables

After syncing, `make sync-sdlc` (and `/sdlc`) now checks the GitHub repo for the secrets and variables the workflows use, counting those shared from its organization. It checks names only, since values can't be read, and prints anything that needs attention:

- **Required and missing:** `CLAUDE_CODE_OAUTH_TOKEN`. Without it the Claude review, `@claude` mentions, spec-from-intent and the agent evals fail. `/sdlc` opens the sync PR as a draft until it's set.
- **The agent App half set up:** some of `SDLC_AGENT_APP_ID`, `SDLC_AGENT_APP_SLUG` and `SDLC_AGENT_APP_KEY` are set but not all. This fails at run time, in spec-from-intent or the Claude review, so it's reported as an error. See [setup-agent-apps.md](https://github.com/stickleprojects/claude-sdlc/blob/main/docs/setup-agent-apps.md).
- **Optional and not set:** the agent App. Without it, spec PRs are opened by `github-actions[bot]` and need someone to click *Approve and run workflows* before their checks run. The Claude review now runs on those PRs too: before this release it failed on them, and the workaround was adding the `review` label.

The check needs `gh` logged in with admin or maintain access to the repo and an `origin` on GitHub. Without a GitHub `origin` or a `gh` login, it's skipped quietly, so the sync still works offline. If `gh` can't read the secret names, the sync says they weren't checked rather than reporting them missing.
