## Fix: every Important finding has a thread, and the gate checks it

On spellbound3d#124 the Claude review listed three Important findings in its summary comment and opened no threads. Conversation resolution only sees threads, so nothing held the merge, and the PR auto-merged half a minute after the review posted (#130).

- **`REVIEW.md` has a new section, *Posting findings*.** Every Important finding is its own thread whose first line starts with `**Important`. A finding no diff line fits, such as a missing change folder or a binary file, goes on the most relevant file as a comment on the whole file (`gh api … -f subject_type=file`; the review is allowed exactly that command). The summary ends with a hidden count line, `<!-- review-findings: important=<N> nit=<M> -->`.
- **`claude-review` checks what the review found, not only that it posted.** After the summary check (`scripts/review-posted.sh`), the new `scripts/review-findings.sh` counts the open `**Important` threads the reviewer started and compares them with the count line. If the line is missing or the numbers differ, the status fails with the reason and asks for the `review` label. When they match, conversation resolution holds the merge until each thread is resolved. That's what makes an approval given before the review posts safe with auto-merge on.
- **The review action no longer drops inline comments.** It ran with `classify_inline_comments` on (the action's default), which holds inline comments back and drops any it judges to be tests when the session ends. It's now off.

A review that lists findings without threads used to pass silently. Now its `claude-review` status turns red.

## Upgrade steps

These are for Claude, as part of `/sdlc`. Do them with the person, after the sync and before `make check`.

1. **A repo on v0.9.x or earlier** gets this only through v0.10's `claude-review` gate. Do v0.10.0's upgrade steps first (`docs/release-notes/v0.10.0.md`), above all re-running bootstrap so main requires `claude-review`. The old `review` check run goes green whenever the job finishes, so on its own it never sees the findings.
2. **Local edits to `REVIEW.md` or `claude-review.yml`.** If the sync lists either as a conflict, keep the framework's new *Posting findings* section and the *Mark the review as done* step whole. Move any project rules into `docs/review-rules.md` (v0.10.0 step 4).
3. **Open PRs** reviewed before this release have no count line, so their next review writes one. Nothing to do until then. A PR whose summary lists Important findings with no threads can be re-reviewed now (`scripts/request-review.sh <N>`): ask the person which.
4. **Report** in the sync PR body whether bootstrap requires `claude-review` yet, and which open PRs had a review requested.
