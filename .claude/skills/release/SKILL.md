# Release the framework

For this repo only (#200); the sync never ships it. Consumers found bugs that the tests and evals missed (#182, the Milestone line), so every release is tried in one first: the trial consumer is `stickleprojects/sdlc-sandbox`. Do the steps with Kieron and stop at the first failure.

1. **What's going out.** Run `gh workflow run release.yml` (a dry run) and show Kieron the version and the notes preview from its run summary. Agree with him that `main` is the commit to release. Every release gets a hand-written `docs/release-notes/<version>.md`, even when nothing seems to need one: what consumers will notice, which workarounds they can drop, and whether the sync changes a review workflow (so its PR gets no AI review). It goes in through its own PR before the trial, so the trial is of the commit that carries it.
2. **Sync.** First, the consumer must be on the last release (its `.sdlc/version`): if it's behind, sync it to that release for real (its own PR, which Kieron merges) before the trial (#292). Otherwise the trial carries older review-workflow changes, and its PR gets no AI review. Then run `scripts/consumer-trial.sh sync`. It pins `main`'s SHA, makes a fresh clone of the consumer in a new scratch folder (never anyone's working checkout), syncs that SHA with the consumer's own sync script and commits it on `chore/sdlc-trial-<sha>`. It prints the folder. If the sync stops on a conflict, or leaves upgrade steps in `.sdlc/upgrade-pending.md`, work through them in that folder with Kieron, as `/sdlc` would, and commit. Each one is a finding.
3. **Check.** Run `scripts/consumer-trial.sh check <folder>`: `make setup` and `make check` in the consumer.
4. **Real PR.** Run `scripts/consumer-trial.sh pr <folder>`. It opens a PR marked do-not-merge, not a draft, since the Claude review skips drafts. Wait for its CI and Claude review, and read both. If `sync` said the PR gets no AI review because this release itself changes a review workflow, there's no review to read: read the workflow diff with Kieron instead.
5. **Findings.** Show Kieron what failed or looked wrong. A framework bug gets an issue, and usually a fix before the release. Then run the dry run again, and the trial again from step 2 if `main` changed. Kieron decides whether a finding blocks the release.
6. **Release.** Write the result as one line, starting as `consumer-trial.sh pr` printed it (the PR and the trial's short SHA), then what passed and what didn't, e.g. `stickleprojects/sdlc-sandbox#12 (claude-sdlc 5df79ee): sync clean, make check and CI passed, review found nothing`. With no AI review, say `review: not run (workflow changed)`, never "review found nothing". The release fails if that SHA isn't the commit it tags: re-run the trial from step 2. Kieron runs `gh workflow run release.yml -f dry_run=false -f trial="<line>"`, or you do once he says to. The release fails without `trial`, and the line goes in the notes under `## Consumer trial`.
7. **Close.** Once the release is out, run `scripts/consumer-trial.sh close <folder>`. It closes the PR, deletes its branch and removes the folder. The consumer then upgrades for real through `/sdlc`, its own PR, which Kieron merges, so the next trial starts from this release (#292).
