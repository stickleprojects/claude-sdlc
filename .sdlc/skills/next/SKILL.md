# What's next

1. **Find where each change is,** following steps 1 and 3 of `.sdlc/skills/routing.md`: `make next REF=origin/main`, plus open PRs and build branches.
2. **Show a short table:** one row per change that isn't done (or just the named change): the change, where it is, the next step, and who it's waiting on (the person, the product owner, the engineer, or a workflow). Link any open PR. List done and withdrawn changes in one line at the end, if there are any. Show an `out of date:` change as gone back a step, with what changed.
   Then one line on the pipeline itself, if it's behind: compare `.sdlc-version` (line 1, `<owner/repo>@<ref>`) with `gh api repos/<owner/repo>/releases/latest --jq .tag_name`. When a newer release exists, say "Pipeline: on v0.4.0, v0.5.0 is out (/sdlc to see what's new)". Say nothing when it's current, when `<ref>` isn't a release tag (`main`, a branch or a commit: `/sdlc` explains where that stands), or when there's no `.sdlc-version` (the framework repo itself).
   **The roadmap,** if the repo has one (`git show origin/main:docs/roadmap.md`; the format is in `.sdlc/docs/roadmap-format.md`): a few lines on the current milestone, the first one that isn't `done`. Give its name and status, its changes that aren't done (with where each is, from the table above), and its exit criteria that aren't ticked yet. If every change in it is done but criteria are still open, say so: the product owner decides whether more changes are needed or the milestone is done. Never reorder the roadmap or mark anything done from here.
3. **Offer the next steps the person can take now,** with AskUserQuestion: up to four, the most advanced change first, each naming the skill it runs (for example "Build 0002-breadcrumbs (/build)", "Work through the review on PR 14 (/pr 14)", "Update the pipeline to v0.5.0 (/sdlc)"). Leave out steps waiting on someone else. With a roadmap, and room for it, include starting the next piece of the current milestone, such as "Start an intent for M2 Phone access: the open exit criterion (/intent)", even when other changes are in flight; when nothing is in flight, put it first.
4. **On a choice,** invoke that skill with the Skill tool, passing the change or PR number, and follow it.
